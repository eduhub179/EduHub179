# tools — что здесь лежит

Два независимых инструмента, оба про «привести чужие файлы в порядок». Сервисом они не
являются: не запускаются постоянно, не слушают порты, ничего не публикуют.

```
tools/
├── drive_ingest/     разовый разбор папки: что за файлы и к какому предмету
└── crawler/          постоянная синхронизация: что появилось/изменилось/удалось
```

## drive_ingest — «посмотреть, что в папке»

Нужен для бэкфилла: учителя ещё не на платформе, материалы лежат в выгрузке Drive или
в архиве. Инструмент проходит папку один раз и пишет отчёт.

| файл | зачем |
|---|---|
| `__main__.py` | команда `scan`: обход, сбор манифеста, отчёт |
| `source.py` | откуда берём файлы: `LocalSource` (папка сейчас), `DriveSource` (заготовка) |
| `extract.py` | текст из PDF/DOCX/PPTX/XLSX/TXT: есть ли текстовый слой, скан это или картинка |
| `classify.py` | правила: предмет, класс, тип. Читает `categories.json` |
| `categories.json` | **предметы и типы с синонимами.** Новый предмет добавляется здесь, код не меняется |
| `test_drive_ingest.py` | проверки без сети и без модели |

Выход: `manifest.jsonl` (строка на файл), `review.csv` (только неясные — работа человеку),
`report.md` (сводка). Файлы **не копируются**: в манифесте остаётся путь, то есть ссылка
на оригинал.

## crawler — «что изменилось с прошлого раза»

Главная вещь: он не переливает диск, а спрашивает у источника «что поменялось с моего
токена». Второй прогон по тем же данным обязан дать ноль событий.

| файл | зачем |
|---|---|
| `__main__.py` | команда `sync` (папка, Drive, или `--fixture` без ключей) |
| `sync.py` | движок: одинаковый для любого источника, пишет `events.jsonl` |
| `state.py` | курсор + отпечатки файлов + кеш имён папок; запись атомарная |
| `transport.py` | настоящий HTTP (`UrllibTransport`) и записанные ответы (`FixtureTransport`) |
| `sources/local.py` | источник «папка на диске»: снимок, сравнение по хешу |
| `sources/drive.py` | источник «Google Drive»: `changes.list`, курсор, путь из `parents` |
| `fixtures/*.json` | записанные ответы Google API — чтобы тесты шли без сети и без ключей |
| `test_sync.py`, `test_drive_source.py` | проверки: created/updated/deleted, страницы, падения, переносы |

### Что такое `fixtures/`

Это **не данные проекта и не конфиг**. Это заменитель Google на время тестов: несколько
JSON-файлов, внутри которых лежат ответы API ровно в том виде, в каком их отдаёт Google
(`{"changes": [...], "newStartPageToken": "T1"}`). `FixtureTransport` подставляет их вместо
сети по ключу запроса (`changes:T0`, `file:P9`, `start`), а если тест попросит что-то, чего
в фикстуре нет, — падает с ошибкой, а не идёт молча в интернет.

```
drive_first.json    первый запуск: startPageToken + список файлов
drive_changes.json  изменения: новый файл, изменённый, удалённый
drive_paged.json    ответ из двух страниц: nextPageToken → newStartPageToken
```

Зачем: без ключей мы всё равно можем проверить логику токенов, пагинации и удалений.
Когда появится service account, эти же тесты останутся, а добавится один живой прогон.
