# files/ — что это за файл и что с ним делать

Пакет отвечает на два вопроса и только на них:

1. **что внутри файла** — текст или картинка, читается или нет (`read.py`);
2. **что это за материал** — предмет, тип, класс (`labels.py` → `decide.py`).

Текст сообщений (ДЗ, контрольные, переносы уроков) здесь **не разбирается**. Это делает
`telegram/chat_agent.py`. Граница проходит по входу: в `files/` попадает файл и его
подпись/чат/путь, а не переписка.

## Поток

```
папка / Google Drive / Telegram
        │
        ▼
   read.py ──────────────► Reading(text, status, engine, pages, ocr_confidence)
        │                        ▲
        │                        └── ocr_triage.py (Tesseract + порог) ── ocr_providers.py
        ▼
   labels.py ────────────► предмет, тип, класс, уверенность
        │  hints.py (подпись → чат → путь)
        │  name_rules.py (тип по имени)
        │  classify/ (модель — только на остаток)
        ▼
   decide.py ────────────► accepted / queued / review / skip
        │
        ├── ingest/   → manifest.jsonl, review.csv, report.md
        ├── crawler/  → events.jsonl, summary.md
        ├── queue.py  → state/file_queue.jsonl, state/file_labels.jsonl
        ├── feed.py   → crawler/ingest уже разметили: их строки становятся метками для act
        ├── due.py    → дата сдачи по расписанию, если в метке её нет (mtime/Drive)
        ├── act.py    → POST /api/lessons/{id}/files (accepted) / state/review.jsonl
        └── Telegram  → карточка/модератор
```

## Файлы

| файл | роль | чего не делает |
|---|---|---|
| `read.py` | единственный читатель: PDF (текстовый слой, иначе рендер + OCR), DOCX, PPTX, XLSX, TXT/код, картинки. Возвращает `Reading` со статусом `native / ocr / scanned / not_downloaded / binary / empty` | не решает, хороший ли это материал |
| `ocr_triage.py` | решает, можно ли доверять Tesseract: порог по словам, цифрам и уверенности. Пишет `state/ocr_queue.jsonl` для будущего движка (VLM запаркован) | не классифицирует предмет |
| `ocr_providers.py` | обёртки OCR-движков; сейчас Tesseract, здесь же точка расширения | — |
| `attachments.py` | Telegram-специфика: скачать вложение, взять подпись, прочитать через `read.py` | не выбирает маршрут |
| `taxonomy.py` | коды предметов школы, русские синонимы, класс из текста, список из `timetable.json`. Незнакомый предмет — `None`, не «ближайший похожий» | не вызывает модель |
| `hints.py` | предмет и класс из подписи → названия чата → пути папки, с пометкой `source` | не определяет тип |
| `name_rules.py` | тип по имени файла: `ДЗ` → homework, `КР` → test, `лист` → worksheet, `плюсник` → plusnik_sheet, `задачник` → textbook, `вариант` → independent_work (medium) | не читает содержимое |
| `labels.py` | оркестратор: подсказки → правила имени → модель только если предмет/тип неизвестны или уверенность ниже `high`. Сводит ответы, пишет `subject_conflict`, ставит `input_mode: heuristic / model` | не выбирает маршрут хранения |
| `classify/` | модель P2: `prompt.md` (шаблон), JSON-схема, строгий `parse()`. Предметы — из `taxonomy`, типы — из `TYPE_HINTS`; честный ответ `unknown` разрешён | не читает файл, текст ему передают |
| `decide.py` | решатель **только для файлов**: `accepted / queued / review / skip` по статусу чтения и меткам. `queued` — очередь OCR, не сообщений | не смотрит текст сообщений |
| `queue.py` | фоновая очередь разметки: `enqueue()` сразу, `process()` позже; JSONL, идемпотентно, 3 попытки на файл. Повторный `enqueue()` того же файла дописывает контекст (подпись, класс), а не теряет его | не запускает сам себя (нужен воркер/таймер) |
| `feed.py` | мост: строки `crawler.run()` и `ingest.scan()` пишутся в `state/file_labels.jsonl` без повторного чтения и модели. Класс берёт из пути («11Б/Физика/…»), иначе `--class`; повтор с тем же хешем не дублируется | не качает файлы и не выбирает маршрут — маршрут уже посчитан в `decide()` |
| `due.py` | дата сдачи по расписанию: уроки предмета, которые ещё не начались на момент появления файла (`seen_at` = mtime или `modifiedTime`). «Через урок» в имени/подписи — берём следующий. Правила те же, что у чатов (`timetable.link`) | не угадывает класс и предмет: без них — review |
| `act.py` | последний шаг: `accepted` + `high` → урок по предмету и дате (`backend_api.find_lesson`) → `POST /api/lessons/{id}/files`. `review` → `state/review.jsonl`, повторно не пишется. `state/file_actions.jsonl` помнит (файл, урок): второй раз не грузим, 413/415/422 не повторяем | не угадывает дату и класс: нет контекста — в review |
| `__init__.py` | пакет | — |

## Кто кого зовёт

- `ingest/` — разовый проход по папке: `read` → `label` → `decide`, пишет манифест.
- `crawler/` — синхронизация источника: те же три шага на каждое событие, пишет `events.jsonl`.
- `queue.py` — отложенная разметка: тот же `label` и `decide`, но после ответа пользователю.
- `act.py` — единственное место, где вердикт превращается в действие: файл уходит в бэкенд
  (`python3 -m eduhub_agent.files.act --apply`), остальное падает в review. По умолчанию dry-run.
- `telegram/attachments.py` — только скачивание и чтение; дальше решает вызывающий код.

Ни один из этих путей не должен иметь собственных порогов: порог один — в `decide.py`.
