# Фото в чатах: что сделано 16.10.2026 и как к этому вернуться

Для беты (понедельник 19.10) включена **заглушка**: фото без подписи сразу считается ДЗ («фото с заданием»), а урок и срок
берутся по расписанию тем же алгоритмом, что у любой домашки (timetable.link). Распознавания нет, модели для фото не нужны.

Всё, что описано ниже, сохранено и включается одной переменной:

```
PHOTO_MODE=board python3 chat_agent.py ...     # вариант с распознаванием (по умолчанию PHOTO_MODE=stub)
```

Копия файлов на момент 16.10 (до заглушки и до метаданных чата):
`варианты/фото-доска-2026-10-16/` (chat_agent.py, files.py, board.py, board_check.py, timetable.py, timetable.json).
Git в папке channel-agent нет, поэтому вместо веток переключатель и эта копия.

## Как работает вариант `board`

Всё работает только на Маке, наружу ничего не уходит.

1. **Скачивание.** В живом режиме бот сохраняет каждое фото и файл из чата в `chats/files/<чат>/` (до 20 МБ, getFile).
   В экспортах фото уже лежат в папке экспорта.
2. **Текст на фото.** Tesseract (rus+eng, файлы tessdata_fast в `agent/tessdata`) читает фото, увеличенное до 1600 px
   в оттенках серого, через `eduhub_agent/media/ocr_triage.py`. Решает не «похоже на текст», а **уверенность самого Tesseract** по словам:
   печатный листок даёт ~90, рукописная доска ~40, и при уверенности ниже 70 (`OCR_MIN_CONF`) текст не берётся.
   Исключение — таблицы чисел (`looks_like_table`: ≥10 чисел, чисел больше, чем слов): там слов мало и уверенность
   считается по трём словам. Принятый текст (первые 2000 символов) идёт в модель вместе с сообщением с пометкой
   «распознано с фото, возможны ошибки», и модель сама решает, ДЗ это или нет.

   Что не прочиталось, но текстом быть может (рукописное, смазанное фото), пишется в `state/ocr_queue.jsonl` —
   это очередь для будущего движка. `ocr_providers.py` уже описывает два: облачный OCR (Яндекс Vision читает
   и рукописный текст) и локальную модель, которая пишет текст с доски, — оба пока выключены, ключей и сети нет.
3. **Фото без подписи и без текста** проверяет модель для картинок (`board.py`, qwen2.5vl:3b через Ollama): «это доска
   с записями?». Да — ДЗ «фото доски с записями» со сроком по расписанию. Нет — фото пропускается.
   Ответы кешируются в `chats/board_cache.json`. Если модели нет, правило не срабатывает и фото разбирает обычная модель.
4. **Фото с подписью** («дз на четверг» + фото) разбирает обычная модель, как любое сообщение.

## Результаты проверок

- Tesseract: на 40 случайных фото из экспортов читаемый текст у 19 (распечатанные задания, объявления), 0,6 с на фото.
  Рукописную доску читает плохо, поэтому для доски нужна отдельная модель.
- PDF и DOCX (работают и в заглушке): текст есть у 208 из 247 PDF и 34 из 38 DOCX, остальное сканы.
- moondream (1,7 ГБ): на 25 фото не нашла ни одной доски, не годится.
- qwen2.5vl:3b (3,2 ГБ): 22 из 25 верно, около 11 с на фото. С qwen2.5:7b в 8 ГБ одновременно не помещается,
  Ollama грузит их по очереди.
- Правило «таблица чисел = текст» потом исправило одну из двух ошибок с таблицами; вторую таблицу Tesseract не прочитал
  (слишком мелкий снимок). Ни одна доска при этом не потерялась.

```
ollama pull qwen2.5vl:3b           # уже скачано
```
