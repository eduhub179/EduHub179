# drive_ingest — разбор папки с материалами

Пока учителя не на платформе, материалы лежат в папках Google Drive (выгрузка Takeout — её пример).
Этот инструмент проходит по папке, понимает, **что за файл**, и раскладывает его по полкам
`класс / предмет / тип`, чтобы потом одним импортом залить в базу.

Ничего не удаляет, не переименовывает и никуда не отправляет. Меняется только папка `--out`.

## Запуск

```bash
# 1. посмотреть, что внутри (5 секунд на 700 файлов, 0.4 с на 47)
python3 -m eduhub_agent.ingest scan "/путь/к/диску" --out out/math

# 2. когда появится доступ к дискам классов — та же команда, другой источник
python3 -m eduhub_agent.ingest scan --drive "<folder_id>" --out out/class-9b
```

`scan` пишет три файла:

| файл | что внутри |
|---|---|
| `manifest.jsonl` | по строке на файл: путь, размер, sha256, MIME по сигнатуре, есть ли текстовый слой, предмет, класс, тип, уверенность |
| `review.csv` | только файлы, у которых не ясен **предмет** — это список для человека, 36 строк из 699 |
| `report.md` | сводка: сколько чего нашлось, что осталось непонятным |

Файлы не копируются и не переименовываются: в манифесте остаётся путь, то есть ссылка
на оригинал. Раскладка по полкам появится, когда будет куда складывать.

## Как решается «что это за файл»

Категории лежат в `categories.json`: предметы и типы с синонимами. Новый предмет (физика,
химия) добавляется строкой в этом файле — код не меняется. Другой файл категорий можно
подставить переменной `EDUHUB_CATEGORIES=/путь/к/categories.json`.

Правила, а не модель. В архивном треке на 280 размеченных файлах правила дают ~77%
совместной точности, gemma3:4b — 73%, qwen2.5:3b — 71%, при 0.05 с против 10 с на файл.
Гибрид (правила + модель на неуверенных) — 88.6%, но модель пока не нужна: неуверенные
файлы дешевле показать человеку списком.

Порядок, в котором смотрят правила:

1. **папки** — `Алгебра/дз/9 класс/` даёт предмет, тип и класс (самый сильный сигнал);
2. **имя файла** — `ДЗ-004`, `КР-2`, `листок 3`, `конспект`;
3. **расширение** — `.pptx` → презентация, `.py`/`.ipynb` → программа;
4. **начало текста** — только если всё выше промолчало.

«Разное», «Не в папках», «Classroom» — не предметы, а свалка: файл оттуда получает
`other_subject` и попадает в `review.csv`, даже если в имени что-то нашлось.

## На чём проверено

| папка | файлов | предмет ясен | тип не ясен, предмет ясен | нужен человек |
|---|---:|---:|---:|---:|
| архив учителя (`Математика Б2027`) | 699 | 484 (69%) | 215 | 0 |
| выгрузка Google Takeout (`Диск`) | 47 | 16 (34%) | 3 | 28 |

По школьным папкам отдельно: Алгебра, Геометрия, Матан — предмет определяется всегда
(100% на размеченном наборе). «Разное» теперь тоже предмет — `misc`, так размечен gold
в треке P2; личные файлы из Takeout, которые ни к какому предмету не относятся, честно
уходят в `review.csv` (28 из 47).

Проверка: `python3 tests/test_ingest.py` — 21 проверка, без сети и без модели.

## Чего пока нет

- **Google Drive не подключён.** `DriveSource` написан как заготовка: нужны service account,
  доступ к дискам классов и `GOOGLE_APPLICATION_CREDENTIALS` + `DRIVE_FOLDER_ID`.
  Остальной код при этом не меняется — источник подменяется одной строкой.
- **Сканы не распознаются.** `text_status = "scanned"` означает «текстового слоя нет»;
  OCR — отдельный шаг (`agent/eduhub_agent/files/ocr_triage.py`), сюда не затянут намеренно.
- **Старые `.doc/.ppt/.xls`** помечаются `binary`: для них нужен LibreOffice, пока не читаем.
- **Тип `other`** — это нормально, а не ошибка: листок с ребусами и правда не ДЗ.

## Синхронизация, а не разовый проход

Этот инструмент — разовый разбор («что лежит в папке»). Постоянное наблюдение за диском
делает `eduhub_agent.crawler`: он хранит состояние, второй прогон даёт ноль событий и отдаёт
только новое/изменённое/удалённое. Планы по Drive/Classroom/Gmail — в `docs/CRAWLER.md`.
