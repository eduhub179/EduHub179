# Агент: находки из чатов и канала школы

Отдельный сервис на Python. Читает Telegram-чаты по предметам и канал школы, находит домашние задания, контрольные, изменения в уроках, материалы и мероприятия. Модель работает локально через [Ollama](https://ollama.com) (qwen2.5:7b), даты, время и кабинеты дополнительно проверяют правила на регулярных выражениях.

Подтверждённые ДЗ и контрольные из чатов уходят в бэкенд через HTTP API (`backend_api.py`, см. ниже). Мероприятия и остальные находки пока сохраняются только локально: для них в API ещё нет адресов.

## Структура

```
agent/
├── chat_agent.py, watch_channel.py, backend_api.py, moderator.py   # запуск: те же команды, что раньше
├── eduhub_agent/              # сам сервис
│   ├── paths.py               # где лежат chats/, tessdata, .env, timetable.json
│   ├── config.py              # env(): переменные окружения и .env
│   ├── telegram/              # всё, что говорит с Telegram
│   ├── media/                 # вложения: PDF/DOCX, фото, распознавание
│   ├── llm/                   # модель, правила, датасет, обучение фильтра
│   ├── server/                # бэкенд EduHub и расписание
│   ├── classify/              # классификатор материалов из трека P2 (промпт + модель)
│   ├── ingest/                # разовый разбор папки: что за файлы (бэкфилл)
│   └── crawler/               # синхронизация источника: что изменилось (Drive/папка)
├── tests/                     # test_*.py и test_*.tsv
├── data/                      # timetable.example.json
├── docs/                      # фото-разбор.md, models_results.md
├── chats/                     # личные данные и кеши (в git не попадают)
├── requirements.txt
└── .env.example
```

Корень `agent/` — по-прежнему рабочая папка: `chats/`, `tessdata/`, `.env`, `timetable.json`
лежат там, а не рядом с модулями (`eduhub_agent/paths.py` — единственное место, где это записано).
Четыре ежедневные команды запускаются короткими обёртками из корня; остальные утилиты — через `-m`.

## Что где

| файл | что делает |
|---|---|
| `chat_agent.py` → `telegram/chat_agent.py` | агент чатов: экспорт чата (`python3 chat_agent.py chats/<экспорт>`) или живой режим через бота (`python3 chat_agent.py live`) |
| `telegram/watch_channel.py` | агент канала школы и канала «Кружочек», опрос раз в 15–30 минут (`python3 watch_channel.py loop`) |
| `telegram/moderator.py` | бот-модератор: каждая находка приходит карточкой с кнопками «Опубликовать» / «Отклонить», на сервер уходит только подтверждённое |
| `telegram/dm.py` | ДЗ, присланное боту в личку: кто прислал — по входу в основном боте, урок — по расписанию, запись от имени этого человека; проверка: `python3 tests/test_dm.py` |
| `telegram/questions.py` | что спросили в личке: ДЗ, расписание, кабинет или новое ДЗ (правила, потом модель); проверка на модели: `python3 -m eduhub_agent.telegram.questions "что у нас в пятницу?"` |
| `telegram/chat_moderation.py` | очередь находок из чатов для того же бота-модератора (`chats/moderation_*.json`, не коммитится) |
| `telegram/fetch_channel.py`, `telegram/kruzhochek.py` | скачивание публичной страницы канала, разбор анонсов «Кружочка» |
| `server/backend_api.py` | подтверждённые ДЗ и контрольные -> `POST /api/homework` / `PATCH /api/homework/{id}/text`; проверка на поддельном сервере: `python3 tests/test_backend_api.py` |
| `server/timetable.py` | расписание для агента: к какому уроку относится ДЗ и к какому сдавать. Источник — `timetable.json` или бэкенд (`TIMETABLE_URL`) |
| `media/files.py`, `media/board.py` | вложения: текст из PDF/DOCX/PPTX, распознавание фото доски (`PHOTO_MODE=board`) |
| `media/ocr_triage.py`, `media/ocr_providers.py` | текст с фото: Tesseract с порогом уверенности, очередь для будущего движка; проверка: `python3 tests/test_ocr_triage.py` |
| `llm/llm_extract.py`, `llm/baseline_rules.py` | мероприятия из постов: модель + правила |
| `llm/train_classifier.py`, `llm/build_dataset.py` | фильтр болтовни (нужны экспорты чатов, в репозиторий не входят) |
| `llm/make_labels.py`, `llm/show_labels.py` | ручная разметка постов канала (`labels.json`); сами посты в репозиторий не входят, там имена учеников |
| `tests/test_agent.py` + `tests/test_*.tsv` | проверка на придуманных сообщениях: `python3 tests/test_agent.py tests/test_final.tsv` |
| `tests/test_timetable.py` | проверка привязки ДЗ к урокам, без модели |
| `classify/` | предмет и тип материала: промпт P2 + JSON-схема, модель из Ollama. Подменяется в тестах параметром `classifier` |
| `ingest/` | разовый проход по папке: `python3 -m eduhub_agent.ingest scan "<папка>" --out out/math` |
| `crawler/` | синхронизация: из папки `agent/` — `python3 -m eduhub_agent.crawler sync "<папка>" --state state/drive.json`; `--fixture` — без ключей |
| `docs/models_results.md` | сравнение локальных моделей |
| `docs/фото-разбор.md` | что сделано с фото 16.10 и как к этому вернуться |

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
ollama pull qwen2.5:7b
cp data/timetable.example.json timetable.json   # и заполнить своим расписанием
.venv/bin/python tests/test_timetable.py
.venv/bin/python tests/test_ocr_triage.py        # чтение фото, без модели
.venv/bin/python tests/test_agent.py tests/test_holdout2.tsv
BOT_TOKEN=*** .venv/bin/python chat_agent.py live --channel  # основной запуск: чаты + каналы + бот-модератор
.venv/bin/python watch_channel.py loop                      # только каналы, если чаты не нужны
```

Утилиты без обёртки запускаются как модули из корня `agent/` (там лежит пакет `eduhub_agent`), например
`python3 -m eduhub_agent.server.backend_api retry`, `python3 -m eduhub_agent.media.board_check 60`,
`python3 -m eduhub_agent.llm.make_labels`.

## Команды бота-модератора

- `/start` — стать модератором (первый, кто напишет; chat_id сохраняется в `moderator.json`)
- `/list` — прислать заново всё, что ждёт решения
- `/manual_channels` — включить или выключить ручную модерацию событий из каналов
- `/manual_chats` — включить или выключить ручную модерацию находок из чатов
- `/manual` — показать, что сейчас включено

Без ручной модерации находки сразу уходят на сервер, а в бот приходит уведомление.

## Что не коммитится

Экспорты чатов и всё в `chats/` (личные переписки), обученный фильтр `*.pkl` (в нём слова из переписок), настоящее расписание с фамилиями учителей, кеши ответов модели и результаты прогонов. Список — в `.gitignore`.

## Как находки попадают в бэкенд

**ДЗ и контрольные (работает).** После кнопки «Опубликовать» в боте-модераторе (или сразу, если ручная модерация чатов выключена) `backend_api.py`:
1. находит id класса через `GET /api/classes` (класс «11Б» из названия чата — это «2027б»: год выпуска + буква), берёт уроки класса на дату срока через `GET /api/classes/schedule/day?date=...&class_id=...` (со всеми группами: английский, профиль) и выбирает урок того же предмета — так находится `lesson_instance_id`;
2. создаёт домашку `POST /api/homework` (автор — `AGENT_USER_ID` с ролью `AGENT_USER_ROLE`, статус `published`), а если у урока домашка уже есть — дописывает свой текст через `PATCH /api/homework/{id}/text`. Текст учителя не трогается;
3. если в чате поправили срок, текст переезжает со старого урока на новый (что куда записано — `api_sent.json`);
4. если сервер недоступен или урока нет в расписании, находка ждёт в `api_queue.json` и повторяется раз в 10 минут, пока срок не прошёл (`python3 backend_api.py retry` — вручную).

**ДЗ из лички боту (`dm.py`).** Ученик или учитель пишет боту, который сидит в чатах (`BOT_TOKEN`), например «физика к пятнице §12, № 5–7»:
1. кто это, бот узнаёт у бэкенда: `GET /api/telegram/users/{telegram_id}` с заголовком `X-Agent-Key` (`AGENT_KEY` в `.env` агента и в `backend/.env`). Связь Telegram ↔ пользователь (`telegram_bindings`) появляется после входа в основном боте EduHub179 по школьной почте; не вошёл — бот просит войти там;
2. класс ученика берётся из профиля, учитель пишет класс в тексте («11Б …»). Предмет — по тексту среди предметов класса, дата — из текста или ближайший урок предмета. Модель разбирает текст так же, как сообщения в чатах; не ответила — всё сообщение считается одним ДЗ;
3. бот показывает, как понял, с кнопками «Записать» / «Отмена» (а если непонятен предмет или в этот день нет урока, кнопками выбирают предмет или день);
4. учитель — запись сразу, автор он сам (`created_by`, роль `teacher`). Ученик — через бота-модератора, как находки из чатов, после подтверждения записывается от имени ученика (роль `student`), ученику приходит «Записал». С `--no-moderator` — сразу.

**Один бот для пользователей.** Если в `.env` агента есть `AGENT_LISTEN=127.0.0.1:8091`, агент сам Telegram не опрашивает: основной бот (`telegram-bot-bin`, у него `AGENT_URL` и тот же `AGENT_KEY`) пересылает ему сообщения из чатов классов, ДЗ в личку от вошедших и нажатия кнопок агента, а отвечает агент тем же токеном (`BOT_TOKEN` = токен основного бота). Вход, команды и всё остальное остаются в основном боте. Отдельным остаётся только бот-модератор, он для модераторов.

**Мероприятия, изменения уроков, материалы — пока нет.** Нужны адреса в API (например, `POST /api/agent/candidates` и создание событий; конец события по умолчанию — начало + 2 часа).

**Что стоит поменять в API.** Адреса не проверяют токен (кроме `/api/telegram/users/...`, там `AGENT_KEY`). Когда проверку добавят везде, агенту хватит того же ключа.

Без `AGENT_LISTEN` бот для чатов должен быть отдельным от основного: оба читают обновления через `getUpdates`, а у одного токена это может делать только один процесс.
