# Что отложено сознательно

Записано 18.10.2026, чтобы не потерялось.

## 1. Читать файлы из Google Drive, когда будет не только ссылка

Сейчас Drive в режиме «только ссылки» (`docs/CRAWLER.md`, вариант 1): событие несёт `fileId`,
путь и ссылку, но содержимое не качается. Поэтому классификатор видит только имя и папку —
отсюда `input_mode: "name_only"` и больше файлов в `review`.

Когда появится доступ к содержимому (service account + права на диск):

1. источник Drive начинает отдавать байты (скачивание по `fileId`, `alt=media`);
2. тот же `files/read.py` читает их как локальный файл — ничего нового писать не нужно;
3. в событии меняется только `input_mode`: `name_only` → `text`;
4. файлы, уже лежащие в состоянии как `name_only`, переклассифицируются одним прогоном
   (у них есть `fileId`, а у состояния — отпечаток).

Скачивать всё подряд не обязательно: вариант 2 — качать только PDF и картинки под лимитом
размера, текстовые форматы (docx/pptx/txt) всё равно не читаются без файла.

## 2. Event emitter: уведомления о новом ДЗ

Краулер уже пишет `events.jsonl` (`created` / `updated` / `deleted`) с предметом, классом,
типом и ссылкой. Не хватает последнего шага — отправить это людям:

- кому: ученикам класса и учителю предмета; адресаты уже есть в бэкенде (`users`, классы),
- что: «по алгебре новое ДЗ: ДЗ-15, ссылка»;
- когда: не ночью, не по одному сообщению на файл — пачкой за прогон;
- защита от повторов: ключ `(source, file_id, kind, hash)` уже есть в событии;
- `deleted` — тихое уведомление учителю, ученикам не отправлять.

Точка входа — тот же событийный поток, отдельный процесс или шаг после синхронизации.
Пока очередь не появится, события просто копятся в файле.
