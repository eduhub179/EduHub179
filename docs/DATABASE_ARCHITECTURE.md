## 1. Введение

Документ описывает схему базы данных для школьной системы, реализующей:

- **Управление пользователями** (ученики, учителя, админы)
- **Учебный процесс** (классы, группы, предметы, уроки)
- **Расписание** (уроки, замены, события, кабинеты)
- **Домашние задания** (текст, файлы, модерация)
- **Плюсник** (матрица "задачи × ученики")

Система спроектирована с учётом:
- Разделения абстракции и конкретики (урок vs конкретный урок на дату)
- Поддержки нескольких учителей на один предмет
- Гибкого расписания (обычные уроки, кружки, лекции, замены)
- Анонимности школьников при редактировании ДЗ
- Полной истории изменений (кто, когда, что поставил/отозвал)

### 2.2 Учебная структура

| Сущность | Назначение |
|----------|------------|
| `classes` | Классы школы (год выпуска + буква) |

|----------|------------|
| `cabinets` | Кабинеты (3-значный номер, этаж) |

### `0002_create_subjects_and_classes.sql`

**Таблицы:**
- `classes` — классы школы
- `subjects` — предметы
- `student_groups` — группы учеников
- `group_members` — состав групп
- `lessons` — абстрактные уроки
- `lesson_teachers` — учителя уроков

**ENUM:**
- `class_letter` — буквы классов ('б', 'в', 'и')

**Ключевые моменты:**
- Номер класса вычисляется из `graduation_year` и текущей даты
- Группы НЕ привязаны к одному классу (могут объединять учеников из разных классов)
- Урок = (класс ИЛИ группа) + предмет (CHECK-ограничение)
- Учителя — отдельная связь (многие-ко-многим)

### `0003_create_schedule.sql` ⚠️

**ВНИМАНИЕ:** выполняется ПЕРЕД `0004` (`homeworks`), так как `homeworks` ссылается на `lesson_instances`.

**Таблицы:**
- `schedule_weeks` — контейнер недели: `week_start_date` (PK), `status` (`draft`/`published`), `copied_from` (self-FK)
- `cabinets` — кабинеты
- `lesson_templates` — шаблоны уроков
- `lesson_instances` — конкретные уроки на даты (одна строка на (шаблон, неделю); `week_start_date` — FK на `schedule_weeks`)
- `events` — события (лекции, мероприятия)
- `event_attendees` — участники событий

**ENUM:**
- `day_of_week` — дни недели (mon–sat; в воскресенье уроков нет — только события)
- `week_parity` — периодичность
- `week_status` — жизненный цикл недели (`draft` / `published`)
- `lesson_instance_status` — статус урока (`scheduled` / `completed` / `cancelled`)

**Функции:**
- `check_teacher_available(teacher, week_start_date, day, start, end, exclude_instance_id)` — недельно-зависимая: сначала инстансы недели (status = 'scheduled'), фолбэк на активные шаблоны для недель без инстансов
- `get_student_schedule_for_date(student, date)` — полное расписание ученика на дату: уроки из **published** недель + события ученика вместе (ничего не скрывается автоматически), с колонкой `status` для серых отменённых уроков

**Ключевые моменты:**
- Шаблон урока = (урок + день + время + кабинет + периодичность)
- Флаг `is_active` в шаблонах — для быстрой проверки занятости
- Флаг `is_override` — всегда FALSE; замены обрабатываются на уровне инстанса
- `lesson_instances` — одна строка на (шаблон, неделю); `week_start_date` ссылается на `schedule_weeks`
- `lesson_instances.cabinet_id` — кабинеты живут на инстансах (еженедельная смена кабинетов); в шаблонах — дефолт-затравка
- Ученики видят только опубликованные недели; проверки занятости видят всё (включая черновики)
- Пересечения (событие vs урок, кружок vs урок) показываются, а не скрываются — решает ученик

```
  ├── ← lesson_teachers.teacher_id (для учителей)

  ├── ← homeworks.last_edited_by

  ├── lesson_id → lessons

  ├── template_id → lesson_templates
  ├── week_start_date
  ├── lesson_date

  ├── cabinet_id → cabinets

  ├── event_id → events

  ├── lesson_instance_id → lesson_instances

  └── homework_id → homeworks

  ├── lesson_id → lessons

  └── ← plusnik_records.sheet_id

plusnik_tasks (задачи)
  ├── sheet_id → plusnik_sheets
  ├── task_number

plusnik_records (плюсы)
  ├── student_id → users
  ├── sheet_id → plusnik_sheets
  ├── task_id → plusnik_tasks
```

## 5. Ключевые архитектурные решения

### 5.1 Разделение абстракции и конкретики

**Уровень 1: Абстрактный урок (`lessons`)**
- Что: класс/группа + предмет
- Пример: "Спецмат в 10б"
- Используется для: плюсника, групп учителей

**Уровень 2: Шаблон урока (`lesson_templates`)**
- Что: урок + день + время + кабинет
- Пример: "Спецмат в 10б, пн 10:50-11:35, каб. 412"
- Используется для: расписания, проверки занятости

**Уровень 3: Конкретный урок (`lesson_instances`)**
- Что: шаблон + неделя + дата
- Пример: "Спецмат в 10б, 28.07.2026 (шаблон T1, неделя 28.07.2026)"
- Используется для: ДЗ, истории, замен на уровне недели

### 5.2 Несколько учителей на один урок

Один урок могут вести несколько учителей (например, Спецмат в 10б ведут 4 учителя).

**Решение:** связь многие-ко-многим через `lesson_teachers`.

**Преимущества:**
- ДЗ, плюсы, расписание — общие для всех учителей
- Нет дублирования уроков
- Легко добавить/убрать учителя

### 5.3 Группы учеников из разных классов

Группы могут объединять учеников из разных классов (например, "Английский B1" — ученики из 10а, 10б, 10в).

**Решение:** `student_groups` не привязана к классу.

**Преимущества:**
- Гибкое разделение по уровням
- Не нужно создавать отдельные классы

### 5.4 Проверка контента ДЗ на уровне приложения

**Проблема:** если проверять на уровне БД (триггер), то при загрузке файла возникает race condition.

**Решение:** проверка в use case + DTO валидация.

**Преимущества:**
- Нет проблем с загрузкой файлов
- Понятные ошибки
- Тестируемость

### 5.5 Плюсник — матрица на лету

**Не храним матрицу** "задачи × ученики" в БД.

**Генерируем на лету:**
```sql
SELECT ... FROM plusnik_tasks t
CROSS JOIN users u
LEFT JOIN plusnik_records pr ON ...
```

**Преимущества:**
- Нет дублирования данных
- Всегда актуальная матрица
- Простота схемы

### 5.6 События и уроки показываются вместе (без автоматического перекрытия)

Если ученик участвует в событии, пересекающемся с уроком — `get_student_schedule_for_date()`
возвращает **обе** строки, пересечение помечается на клиенте; решение принимает ученик.
Ничего не скрывается автоматически. Урок, заменённый обязательным
событием, отменяется через статус инстанса, а не через перекрытие.

### 5.7 Шаблоны уроков с флагами

**`is_active`:**
- TRUE — шаблон используется в текущем расписании
- FALSE — архивирован, не участвует в проверке занятости
- Позволяет быстро проверять занятость учителя

**`is_override`:**
- TRUE — шаблон для замены
- FALSE — обычный шаблон
- Упрощает архивацию замен

## 6. Сценарии использования

### 6.1 Ученик открывает расписание на день

```sql
SELECT * FROM get_student_schedule_for_date('student_id', '2026-07-28');
```

**Результат:**
```
09:00-09:45  Алгебра (каб. 412)
09:55-10:40  Русский язык (каб. 305)
10:50-11:35  Лекция по квантовой физике (актовый зал)  ← событие перекрывает урок
11:55-12:40  История (каб. 201)
```

### 6.2 Учитель создаёт ДЗ

```rust
// 1. Валидация: хотя бы текст или файл
if cmd.text_content.is_none() && cmd.files.is_empty() {
    return Err(DomainError::EmptyHomework);
}

// 2. Загрузка файлов в S3
let file_records = file_storage.upload_files(cmd.files).await?;

// 3. Создание ДЗ + файлов в одной транзакции
let homework = homework_repository.create_with_files(cmd, file_records).await?;
```

### 6.3 Учитель ставит плюс

```sql
INSERT INTO plusnik_records (student_id, sheet_id, task_id, granted_by)
VALUES ('student_id', 'sheet_id', 'task_id', 'teacher_id');
```

**Fail-safe:**
- Уникальный индекс не даёт поставить два плюса за одну задачу
- Триггер проверяет принадлежность задачи листку

### 6.4 Админ составляет расписание

```sql
-- Неделя должна существовать раньше (FK)
INSERT INTO schedule_weeks (week_start_date, status)
VALUES ('2026-07-27', 'draft');

-- Проверяем, занят ли учитель В ЭТУ НЕДЕЛЮ (недельно-зависимая проверка)
SELECT check_teacher_available('teacher_id', '2026-07-27', 'mon', '10:50', '11:35');

-- Создаём шаблон урока
INSERT INTO lesson_templates (lesson_id, day, start_time, end_time, cabinet_id)
VALUES ('lesson_id', 'mon', '10:50', '11:35', 'cabinet_id');

-- Создаём экземпляр урока на неделю (ячейка сетки)
INSERT INTO lesson_instances (template_id, week_start_date, lesson_date)
VALUES ('template_id', '2026-07-27', '2026-07-27');

-- Публикуем, когда неделя готова
UPDATE schedule_weeks SET status = 'published' WHERE week_start_date = '2026-07-27';
```

**Примечание:** в стабильный период неделя обычно строится *копированием предыдущей*
(ячейки копируются 1:1, замены добавляются вручную) — см. docs/SCHEDULE.en.md.

### 6.5 Замена урока (учитель заболел)

```sql
-- Создаём шаблон для замены
INSERT INTO lesson_templates (lesson_id, day, start_time, end_time, cabinet_id, is_override, comment)
VALUES ('new_lesson_id', 'mon', '10:50', '11:35', 'cabinet_id', TRUE, 'Иванов заболел');

-- Переводим урок этой недели на шаблон замены
UPDATE lesson_instances
SET template_id = 'new_template_id'
WHERE instance_id = 'instance_id';
```

### 6.6 Часть класса уходит на лекцию

```sql
-- Создаём событие
INSERT INTO events (title, start_time, end_time, cabinet_id, organizer_id)
VALUES ('Лекция по квантовой физике', '2026-07-28 10:50', '2026-07-28 11:35', 'cabinet_id', 'teacher_id');

-- Добавляем участников
INSERT INTO event_attendees (event_id, student_id) VALUES
    ('event_id', 'student_1'),
    ('event_id', 'student_2');
```

**Расписание ученика:**
- Если ученик участвует в событии → возвращаются И событие, И урок;
  пересечение помечается на клиенте, решение принимает ученик (ничего не скрывается
  автоматически)

## 7. Порядок выполнения миграций

```
0001_create_users.sql              ← независим
    ↓
0002_create_subjects_and_classes.sql ← зависит от 0001
    ↓
0003_create_schedule.sql           ← зависит от 0002
    ↓
0004_create_homework.sql           ← зависит от 0003 (lesson_instances)
```
