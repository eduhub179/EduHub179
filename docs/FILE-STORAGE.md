# Файлы: что уже есть, что строить и что можно сделать без VPS

Дата: 18.10.2026. Проверено по коду `origin/main` (`2f2a6c0`), не по документации.

---

## 1. Что уже сделано

| слой | что есть | файл |
|---|---|---|
| БД | таблица `homework_files`: `storage_key`, `file_name`, `mime_type`, `size_bytes`, `sort_order`, каскад по `homework_id` | `migrations/0004_create_homework.sql` |
| домен | `HomeworkFile` + `try_new` (обрезка, лимиты 500/255/100 символов, размер ≥ 0) | `domain/entities/homework.rs` |

| инфраструктура | `S3FileStorage` — **заглушка в памяти** (`HashMap<String, Vec<u8>>`) | `infrastructure/storage/s3_file_storage.rs` |

Вывод: **метаданные и бизнес-логика готовы, байтов нет.** Ровно половина системы.

## 2. Чего нет

1. **HTTP-поверхности.** В `router.rs` ни одного маршрута для файлов, `AppState` не знает про `FileStorage`. Загрузить файл с клиента физически некуда.
2. **Настоящего хранилища.** `S3FileStorage` держит байты в памяти процесса: рестарт — файлы исчезли, между инстансами не разделяются, память течёт.
3. **Конфигурации.** В `infrastructure/config.rs` нет ни `S3_ENDPOINT`, ни ключей, ни бакета.
4. **Авторизации на маршрутах.** Мидлвари с JWT нет вообще: любой, кто знает URL, может скачать чужой файл или залить свой.
5. **Уборки.** `ON DELETE CASCADE` удаляет строки, но не объекты: удалили домашку — блобы остались сиротами.
6. **Классификации.** MIME берётся на веру от клиента, никакой проверки по сигнатуре.

## 3. Находки, которые надо починить до продакшена

- **Ключ объекта = `homeworks/<имя файла>`.** Два ученика присылают `ДЗ.pdf` — второй затирает первый. Ключ обязан содержать UUID.
- **MinIO в compose без тома и healthcheck.** `volumes:` объявляет только `pgdata`, значит данные MinIO живут в слое контейнера и умирают при пересоздании.
- **Лимит 100 МБ.** Для фото с телефона это много: 100 МБ × 10 файлов на домашку × 30 классов — и диск VPS кончается. Фото — 10-15 МБ, PDF — 25 МБ.
- **Загрузка целиком в память** (`Vec<u8>` в команде и в порте). Один 100-мегабайтный аплоад на 4 ГБ хосте — это OOM.

## 4. Как строить

Порт `FileStorage` уже правильный, менять его не нужно. Строим два адаптера и маршруты.

### 4.1 Адаптеры

| драйвер | когда | как |
|---|---|---|
| `local` | сейчас, локальная разработка, односерверный VPS | `data/files/<ключ>`, атомарная запись через `tmp` + `rename` |
| `s3` | VPS с MinIO или Yandex Object Storage | aws-sdk-s3 или крейт `object_store`, `path_style=true` для MinIO |

Выбор — переменной `STORAGE_DRIVER`. Код приложения не меняется: `Arc<dyn FileStorage>`.

### 4.2 Ключи

```
homeworks/{homework_id}/{file_id}{ext}
```
UUID в ключе убирает коллизии, префикс по домашке даёт удаление одной операцией и понятную раскладку на диске.

### 4.3 Поток загрузки

Сейчас — **через бэкенд**: клиент → `POST /api/homework/{id}/files` (multipart) → проверка прав → сигнатура → лимит → `FileStorage::upload` → `add_file` в БД. Плюсы: авторизация, проверка типа, аудит, не нужен публичный бакет. Минус: трафик идёт через приложение.

Позже, если файлы станут большими: **presigned PUT** — клиент льёт напрямую в S3 по подписанной ссылке, бэкенд только выдаёт ссылку и принимает метаданные. Это следующий шаг, не первый.

### 4.4 Поток скачивания

`GET /api/files/{file_id}` → права → `FileStorage::download` → поток в ответ (`Content-Type`, `Content-Disposition`, `ETag`). Бакет **не публичный**. Presigned GET с TTL — когда появится CDN или мобильный кеш.

### 4.5 Классификация

1. **Сигнатура, а не заголовок клиента:** крейт `infer` по первым байтам; заявленный `image/jpeg`, а внутри PDF — отказ.
2. **Белый список:** `image/jpeg`, `image/png`, `application/pdf`, `application/vnd.openxmlformats-officedocument.*` (docx/pptx).
3. **Превью** для картинок (например, `image` + `webp` 400 px) — чтобы список домашек не тянул оригиналы.
4. **Текст** — не сейчас. Когда понадобится, это тот же `ocr_triage` из агента, вызываемый после загрузки (очередь уже есть).

### 4.6 Гигиена

- лимиты: 15 МБ фото, 25 МБ документ, 10 файлов на домашку, квота на класс;
- `DELETE /api/files/{id}` → объект + строка;
- фоновый уборщик: объекты без строки в БД старше суток (и наоборот) — раз в сутки;
- счётчик занятого места на бакет/класс — просто `SELECT sum(size_bytes)`.

## 5. Что можно сделать **сейчас**, без VPS и без Google Drive

Всё, кроме реального S3:

1. `LocalFileStorage` — рабочий адаптер, пригодный и для односерверного VPS.
2. Маршруты загрузки/скачивания/удаления + тесты на временной папке (`tempfile`), без сети.
3. **MinIO локально**: `docker compose up minio` на ноутбуке — это тот же S3 API, что на VPS. Ничего не стоит, ключи задаются в `.env`.
4. Конфиг через env: `STORAGE_DRIVER`, `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_REGION`.
5. Починить compose: том `miniodata`, healthcheck, one-shot контейнер `mc mb` для создания бакета.

**«Потом просто добавить ключи»** — это буквально: на VPS поставить MinIO (или взять Yandex Object Storage), прописать пять переменных и выставить `STORAGE_DRIVER=s3`. Код не трогаем.

Google Drive не нужен ни на одном шаге. Он был источником старых файлов, а не хранилищем системы; если понадобится разовый импорт — это отдельный одноразовый скрипт поверх того же `FileStorage`.

## 6. Порядок работ

| шаг | что | зачем |
|---|---|---|
| 1 | `LocalFileStorage` + ключи с UUID + тесты | байты перестают жить в памяти |
| 2 | `STORAGE_DRIVER` + конфиг + проводка в `AppState` | выбор хранилища без правки кода |
| 3 | `POST /api/homework/{id}/files`, `GET /api/files/{id}`, `DELETE` + лимиты | появляется HTTP-поверхность |
| 4 | сигнатура + белый список MIME + превью | файл нельзя выдать за другой |
| 5 | MinIO в compose с томом и healthcheck | локально то же, что на VPS |
| 6 | уборщик сирот | диск не растёт молча |
| 7 | JWT-мидлварь на файловые маршруты | **обязательно до первого публичного запуска** |

Шаг 7 технически не про файлы, но без него файловый API нельзя выпускать: сейчас в роутере нет ни одной проверки токена.
